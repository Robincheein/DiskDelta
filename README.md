从 [GitHub Releases](https://github.com/Robincheein/DiskDelta/releases/latest) 获取 `DiskDelta.exe`，双击即可打开面板。程序使用 Windows 10/11 自带的 .NET Framework，支持 Windows 高 DPI 缩放。

1. 在顶部 **扫描磁盘** 选择盘符，再点 **立即扫描**。第一次建立基准，再扫一次就能比较。
2. 在 **目录树** 展开文件夹，查看两次快照的大小及净变化。父目录的数字包含子目录。悬停可看直属文件的净变化，右键可打开目录或复制路径。
3. 可在 **增长文件** 查看新增和增大的文件，双击可在资源管理器中定位。
4. 在 **设置 → 扫描计划** 选择磁盘、启用每日扫描并设置时间，再点 **保存计划**。默认时间为 20:00。任务按盘符和磁盘身份识别目标，可在 Windows 账户登录时后台运行。移动 EXE 后，可在原计划所在的盘符重新保存来更新任务路径。

点击 **目录树** 或 **增长文件** 的表头切换升序和降序。目录树只调整同级目录的顺序，保留展开状态。增长默认显示为红色，减少为蓝色，可在顶部 **设置 → 变化颜色** 分别更改或恢复默认。

快照优先与上一个有记录日期的最后一次扫描比较。只有当天有记录时，使用当天的第一份。数据保存在 `%LOCALAPPDATA%\DiskDelta`。每个磁盘保留最近 30 个有扫描记录的日期中的每次成功扫描，以及最近四份完整索引和当前基准索引。打开旧版对比时，如果两份完整索引都还在，程序会自动重建目录大小。如果索引已经轮换，只能显示旧版留下的目录增长量。

树中显示有变化的文件夹及其祖先，大小按两次快照中可比较的文件的逻辑大小汇总。磁盘占用变化来自 Windows 的实际可用空间。权限受限目录、硬链接、压缩或稀疏文件和文件系统元数据会影响两者的对应关系。移动或重命名会记录为路径变化。

## 历史记录与托盘

**历史记录** 展示所选盘的可用空间趋势。左侧默认勾选最近两条记录，勾选第三条时会替换最早勾选的一条。任意两条已保存的记录都能比较可用空间和占用变化。如果两份完整索引仍在，或之前保存过这组对比，可以打开文件和目录差异。双击记录可查看当时保存的对比。

在 **设置 → 常规** 可开启开机自启动和系统托盘。自启动在当前 Windows 用户登录后运行。开启托盘后，自启动、关闭窗口和最小化都会收进托盘。双击托盘图标恢复，右键菜单可退出。

## 版本更新

每次启动会在后台查询 GitHub。**设置 → 版本更新** 可手动检查，有新版时可选择下载安装。程序使用 GitHub Release 的 SHA-256 和版本号校验下载文件，退出旧进程后替换同一个 EXE 并重新打开。

仓库是私有仓库，更新使用本机 Git Credential Manager 中有仓库访问权限的 GitHub 登录。也可打开 **发布页** 下载安装。更新支持系统代理或 Git 的 HTTP 代理，必要时可单独填写应用的 HTTP 代理。

## 安全清理

首次进入 **安全清理** 会自动扫描，以后打开显示上次结果和时间，点 **扫描项目** 更新。点一项可看清理后的影响、实际扫描的路径、文件树和跳过原因。文件特别多时，可手动展开深层目录或双击「显示更多文件」。右键文件夹可打开，右键文件夹或文件可在资源管理器中定位并复制完整路径。

清理项目包括用户 Temp、Windows Temp 中符合条件的临时文件、浏览器缓存、DirectX 着色器缓存、缩略图、图标、远程桌面位图和诊断记录。浏览器支持 Chrome、Edge、Brave、Vivaldi、Opera、Opera GX 和 Firefox。软件缓存包含 VS Code、VS Code Insiders、Cursor、Qoder 和 Discord。微信和 QQ 在支持的默认位置及固定盘根目录查找 `.tmp` 和 `.temp` 文件，保留聊天数据库、附件和配置。 [BleachBit 清理规则](https://github.com/bleachbit/bleachbit/tree/master/cleaners) · [Dism++ 清理规则](https://github.com/Chuyu-Team/Dism-Multi-language/blob/master/Data.xml#L3719-L3915)

扫描按各项目的目录和文件类型查找候选文件，不限制创建或修改时间。列表默认全不勾选，清理只执行勾选并确认的项目。程序跳过联接、硬链接、正在使用或预览后发生变化的文件。浏览器、聊天软件或其他相关应用运行时会跳过对应缓存。

**Windows 回收站** 显示当前用户跨盘的项目数、大小和按原目录组织的预览。右侧可打开 Windows 回收站，按项还原或删除。勾选该类别后，清空整个回收站会另弹 Windows 确认。**Windows 磁盘清理** 仍可用于系统提供的额外项目。 [Microsoft 磁盘清理文档](https://learn.microsoft.com/windows-server/administration/windows-commands/cleanmgr) · [Windows Shell 回收站](https://learn.microsoft.com/en-us/windows/win32/shell/functions)

**查找重复文件** 在所选范围内按实际所在的文件夹分别比较大小和 SHA-256，文件名可以不同。可包含子文件夹，每个子文件夹仍分别比较。结果默认全不勾选，可双击文件在资源管理器中定位。确认删除前会再次逐字节比较并锁定一份保留文件。如果无法验证至少一份保留文件，该组会跳过，清理会永久删除通过验证的已勾选文件。

## 目录迁移

点击页面标题旁的 **?** 可查看迁移示例、备份释放条件和恢复方式。

首次打开 **目录迁移** 会检查当前用户的点目录、AppData 应用子目录、这些应用的一级缓存目录和链接，以及 C 盘两个 Program Files 目录。子目录默认折叠，可按名称搜索或点表头在同级内排序。占用大小为本地文件的逻辑大小，链接目标、未测量的目录和无法完整读取的目录显示「—」。目录联接和符号链接显示保存的目标，右键可复制完整路径。

默认 **推荐目录** 展示达到 32 MB、未发现阻止条件的已识别缓存，以及用户已有的非系统链接。32 MB 是列表筛选条件。可切到「用户目录」查找其他应用数据，或切到「全部目录」查看有疑点的目录和原因。预检会识别下级链接、云占位、加密、读取失败及安装目录中的驱动文件。迁移执行前还会检查整个源目录。Steam 游戏可通过 Steam 自带的存储管理移动。 [微软系统目录说明](https://learn.microsoft.com/en-us/troubleshoot/windows-server/user-profiles-and-logon/relocation-of-users-and-programdata-directories) · [Steam 支持](https://help.steampowered.com/en/faqs/view/4bd4-4528-6b2e-8327)

退出相关软件，选择当前用户在 C 盘的单个应用配置或缓存目录，再选择其他固定 NTFS 盘上的目录。「目标位置」显示实际迁移路径。末级名称与源目录不同时会自动补上源目录名，已经填写完整路径时直接使用。确认迁移后会创建缺少的目录，空目标可复用。程序复制文件并核对内容和数据流，然后在原路径建立 NTFS 目录联接。受保护的系统目录、嵌套联接、云占位和加密文件会阻止迁移。

页面底部的 **迁移日志** 实时显示执行命令、Robocopy 输出和退出码，以及创建目录、核对文件、建立联接、恢复和备份释放的步骤。

安装目录只允许系统安装登记明确指向且通过权限检查的独立软件目录。共享目录、系统组件、登记了服务或驱动的目录及包含驱动文件的目录会被阻止。选择目标盘后会显示实际路径，程序将使用该盘的 `DiskDelta-ProgramFiles` 专用目录。必须勾选风险确认并授权管理员权限。软件启动、自动更新、安装修复或卸载仍可能受影响，验证前请保留 C 盘备份。

迁移会保留原盘备份。验证软件可以正常打开后，选中迁移记录可以恢复原目录，或重新核对文件后释放备份。恢复会保留目标盘现有数据。目标内容与备份不一致时，程序会保留 C 盘备份。

## 软件位置

从 Windows 的卸载登记和 App Paths 读取桌面软件，再读取当前用户的应用包安装位置。首次进入会自动扫描所有盘符，以后打开显示本地保存的结果。点 **扫描所有盘符** 会检查所有就绪盘符内能访问的目录与程序名。可按名称或发布者筛选。右侧区分登记位置和同名线索，可展开目录或右键定位。名称匹配需要核对，未登记的任意文件无法仅凭注册表确定归属。全盘扫描时间随文件数和磁盘速度变化。
